## 4. The Method

**Eyebrow:** The Method
**H2:** Six rules. Each has a test.

1. **Write the intent, the accountable party, and the failure boundary before the work.** Test: is there a plain-English record a stranger could read, does it name whose paper this falls under, and does it say what survives and who restarts if the named person, vendor, or tool dies mid-engagement?
2. **Enforcement travels with the code.** Test: can the rule be bypassed by working from a different machine? If yes, it is not enforced.
3. **Prove it before you call it done, and keep proving it.** Test: where is the evidence, could a stranger re-run it today, is it dated, and is there a scheduled re-check with a named owner tied to the model, vendor, or tool it depends on?
4. **Every change explains itself to an outsider.** Test: a stranger reading only the change can say what changed, why, where it sits, how it was verified, how to roll it back, what the risks are, and what is unfinished.
5. **Memory is governed, cited, append-only, and replicated off the machine that wrote it.** Test: if that machine died tonight, does the receipt still exist, and can a stranger re-verify it without asking us?
6. **People before P&L, on the record.** Test: before any decision that trades money against a named person's situation, is there a dated note, written before the decision, naming who was asked and what the money-favorable option would have been?

**Closing line:** Passes all six, it is Intent Solutions work, whoever did it and whatever model they used. Fails one, it is not.

**Link:** The method as software → https://github.com/jeremylongshore/audit-harness
